# EGOS — Agricultural Yield & Care Assistant

EGOS — запускаемый Telegram-бот для фермеров. Он принимает геолокацию поля,
получает погоду именно для этой точки, делает прозрачную демонстрационную
оценку урожайности и формирует рекомендации по поливу и уходу на 7 дней.

> Важное ограничение: оценка урожайности в MVP не является научно
> подтверждённым прогнозом. Она не заменяет агрономическое обследование или
> валидированную модель.

## Возможности

- `/start` — главное меню;
- `/demo` — готовый сценарий для презентации;
- геолокация через Telegram Location или ручной ввод latitude/longitude;
- культуры: пшеница, кукуруза, подсолнечник, картофель и произвольная культура;
- площадь, дата посева, наличие орошения и удобрений;
- WeatherAPI.com для текущей погоды и 7-дневного прогноза;
- SQLite + SQLAlchemy для пользователей, полей и истории прогнозов;
- план ухода с погодными условиями, риском, действием и причиной на каждый день;
- FastAPI endpoints `/` и `/health` для проверки процесса.

## 1. Установка Python

Нужен Python 3.11 или новее:

```bash
python3 --version
```

## 2. Virtual environment

Из корня проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

В Windows PowerShell:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
```

## 3. Зависимости

На обычном Python установите зависимости так:

```bash
python -m pip install --upgrade pip
python -m pip install -r egos/requirements.txt
```

В Replit зависимости проекта уже устанавливаются в окружение Python.
Если команда `python -m pip` отвечает `No module named pip`, не нужно
устанавливать `psycopg2` или PostgreSQL: EGOS использует встроенную SQLite.
Запускайте бота напрямую командой из раздела запуска.

## 4. Telegram-бот через BotFather

1. Откройте Telegram и найдите `@BotFather`.
2. Выполните `/newbot`.
3. Задайте имя и username бота.
4. Скопируйте токен, но не добавляйте его в код и не публикуйте в Git.

## 5. Ключ погоды

Создайте бесплатный ключ на [WeatherAPI.com](https://www.weatherapi.com/).
Бот использует endpoint `forecast.json` и передаёт в параметре `q` точную
пару координат поля: `latitude,longitude`.

## 6. Файл `.env`

Скопируйте пример:

```bash
cp egos/.env.example egos/.env
```

Заполните `egos/.env`:

```dotenv
BOT_TOKEN=токен_из_BotFather
WEATHER_API_KEY=ключ_WeatherAPI
DEMO_MODE=false
```

Для презентации без ключа погоды:

```dotenv
BOT_TOKEN=токен_из_BotFather
WEATHER_API_KEY=
DEMO_MODE=true
```

`BOT_TOKEN` нужен всегда для запуска Telegram polling. `WEATHER_API_KEY`
нужен только при `DEMO_MODE=false`.

## 7. Запуск

Из корня проекта:

```bash
source .venv/bin/activate
python -m egos.bot
```

В Windows:

```powershell
.venv\Scripts\Activate.ps1
python -m egos.bot
```

Health endpoint будет доступен на `http://127.0.0.1:8000/health`.
SQLite-файл `egos.db` создаётся в текущей директории запуска.

## Пример работы

1. Пользователь отправляет `/start`.
2. Нажимает `🌾 Создать прогноз`.
3. Отправляет Location или вводит `43.2389, 76.8897`.
4. Выбирает `Пшеница`.
5. Вводит `50`.
6. Вводит дату посева `15.04.2026`.
7. Выбирает орошение и удобрения.
8. Добавляет примечание или нажимает `Пропустить`.
9. EGOS показывает название ближайшего места из ответа погодного API,
   диапазон т/га, общий урожай, погодные риски, полив и ближайшие действия.
10. `📋 Полный план` показывает минимум 7 дней. `📊 История` показывает
    дату, культуру, площадь и диапазон урожайности.

Команда `/demo` быстро проходит сценарий с подготовленными данными Алматы,
показывая все стадии: геолокация → культура → площадь → посев → API →
анализ → прогноз → план.

## Что является демонстрационным

- `services/yield_model.py` содержит базовые коэффициенты культур и небольшие
  корректировки за температуру, осадки, орошение и удобрения. Коэффициенты
  вынесены в `CROP_PROFILES` и легко заменяются.
- `DEMO_MODE=true` использует подготовленный 7-дневный погодный ответ, но
  интерфейс и расчётный pipeline остаются теми же.
- План ухода — осторожные рекомендации для наблюдения, а не гарантированные
  агрономические решения.

Для настоящей ML-модели нужно заменить `calculate_yield` на версионированный
модуль с валидированным локальным датасетом, признаками почвы и сорта,
агротехнологиями, историей погоды, оценкой качества, доверительными
интервалами и регулярной валидацией агрономами. `WeatherData` уже отделён от
модели, поэтому источник погодных данных можно заменить без переписывания
Telegram-сценария.
